# M5Faces Calculator3 I2C 控制协议

| 文档信息 | 内容 |
| :--- | :--- |
| 产品名称 | M5Faces Calculator3 |
| SKU | `A005-V3` |
| 适用固件 | `v03` |
| 接口类型 | I2C |
| 文档语言 | 简体中文 |

---

## 1. 硬件接口

| 项目 | 说明 |
| :--- | :--- |
| 默认 I2C 从机地址（7 位） | `0x08` |
| 建议配置地址范围 | `0x08`-`0x77` |
| 通信速率 | Standard Mode `100 kbps` / Fast Mode `400 kbps` |
| IRQ 有效电平 | 低电平有效 |
| 按键数据长度 | 每次读取 1 字节 |
| 长按判定时间 | 大于 `400 ms` |

### 1.1 IRQ 行为

按键松开并产生一个有效按键码后，模块将 `IRQ` 拉低。主机直接读取 1 字节按键数据后，模块将 `IRQ` 恢复为高电平。

```text
按键松开并产生数据                 主机读取按键数据
        │                               │
────────┘ IRQ 低电平（0）────────────────┘ IRQ 高电平（1）
```

> 任意 I2C 读取事务结束时固件都会释放 `IRQ`。当 `IRQ` 为低电平时，主机应先读取按键数据，再读取配置寄存器。

---

## 2. 通信操作概览

模块支持以下三类 I2C 操作：

| 操作 | 主机访问格式 | 用途 |
| :--- | :--- | :--- |
| 按键数据读取 | 直接读取 1 字节 | 获取最近一次产生的按键码并释放 IRQ |
| 寄存器读取 | 写入 1 字节寄存器地址，然后读取 | 获取设备 ID、UID、固件版本或当前 I2C 地址 |
| 命令写入 | 写入 `[寄存器地址] [数据]`，共 2 字节 | 进入 IAP 启动流程或修改 I2C 地址 |

所有多字节数据均按表中从左到右的顺序传输。

---

## 3. 按键数据读取

当 `IRQ` 为低电平时，主机直接从模块读取固定 1 字节，无需先写寄存器地址。按键数据在按键松开时产生。

### 3.1 按键矩阵与返回值

模块使用 5 行 x 4 列按键矩阵。普通短按返回对应字符的单字节 ASCII 码。

| 行 / 列 | Col 0 | Col 1 | Col 2 | Col 3 |
| :---: | :---: | :---: | :---: | :---: |
| Row 0 | `A` (`0x41`) | `M` (`0x4D`) | `%` (`0x25`) | `/` (`0x2F`) |
| Row 1 | `7` (`0x37`) | `8` (`0x38`) | `9` (`0x39`) | `*` (`0x2A`) |
| Row 2 | `4` (`0x34`) | `5` (`0x35`) | `6` (`0x36`) | `-` (`0x2D`) |
| Row 3 | `1` (`0x31`) | `2` (`0x32`) | `3` (`0x33`) | `+` (`0x2B`) |
| Row 4 | `.` (`0x2E`) | `0` (`0x30`) | `` ` `` (`0x60`) | `=` (`0x3D`) |

### 3.2 长按特殊码

只有 `A` 和 `=` 定义了长按特殊行为。按住超过 `400 ms` 后松开时返回以下控制码：

| 按键 | 短按返回值 | 长按返回值 | 长按含义 |
| :---: | :---: | :---: | :--- |
| `A` | `0x41` | `0x08` | Backspace |
| `=` | `0x3D` | `0x0D` | Carriage Return（CR） |

其他按键长按后仍返回其普通 ASCII 码。

### 3.3 事件缓存

模块只保留一个待读取的按键字节，不提供按键 FIFO。若主机读取前又产生新的按键数据，旧数据可能被覆盖。主机应在检测到 `IRQ` 低电平后尽快读取。

## 4. 寄存器地址映射

| 寄存器地址 | 可读 | 可写 | 默认值 / 返回值 | 说明 |
| :--- | :---: | :---: | :--- | :--- |
| `0xD0` | 是 | 否 | `0x01` | 设备类型 ID（Calculator） |
| `0xE0`-`0xEB` | 是 | 否 | 设备相关 | 96-bit MCU UID，共 12 字节 |
| `0xFD` | 否 | 是 | - | 系统复位 / IAP 启动命令 |
| `0xFE` | 是 | 否 | `0x03` | 固件版本号 |
| `0xFF` | 是 | 是 | `0x08` | I2C 地址寄存器 |

> 未列出的地址不属于公开控制协议，主机不应依赖其返回值或写入行为。

---

## 5. 寄存器读取

### 5.1 读取流程

1. 主机向模块写入 1 字节寄存器地址。
2. 主机发起重复起始条件或新的 I2C 读取事务。
3. 模块从所选地址开始返回该寄存器段的数据。

主机读取的字节数不得超过下表给出的最大长度。

### 5.2 可读寄存器段

#### 设备类型 ID

| 起始地址 | 可读字节数 | 返回数据 |
| :--- | :---: | :--- |
| `0xD0` | 1 | `[0x01]` |

#### MCU UID

| 起始地址 | 最大可读字节数 | 返回数据 |
| :--- | :---: | :--- |
| `0xE0`-`0xEB` | `0xEC - 起始地址` | 从对应偏移开始的 UID 剩余数据 |

UID 在设备上电时读入缓存。完整 UID 从 `0xE0` 开始读取 12 字节，字节顺序与 STM32 UID 存储地址递增顺序一致。

#### 固件版本号和 I2C 地址

| 起始地址 | 可读字节数 | 返回数据 |
| :--- | :---: | :--- |
| `0xFE` | 2 | `[firmware_version, i2c_address]` |
| `0xFF` | 1 | `[i2c_address]` |

固件 `v03` 的 `firmware_version` 返回 `0x03`。`i2c_address` 为当前使用的 7 位从机地址，不包含读写方向位。

## 6. 命令写入

公开命令的写入格式固定为 2 字节：

```text
[寄存器地址] [数据]
```

### 6.1 系统复位 / IAP 启动（`0xFD`）

| 写入数据 | 行为 |
| :---: | :--- |
| `0x01` | 触发模块进入 bootloader / IAP 启动流程 |
| 其他值 | 无操作 |

示例：

```text
[0xFD] [0x01]
```

> 本文档仅定义应用固件中的 IAP 入口，不定义后续固件传输协议。

### 6.2 修改 I2C 地址（`0xFF`）

| 项目 | 说明 |
| :--- | :--- |
| 建议地址范围 | `0x08`-`0x77` |
| 固件接受范围 | `0x01`-`0x7F` |
| 生效时间 | 写入事务完成后生效 |
| 掉电保存 | 是，存储在内部 Flash 中 |

I2C 规范保留了 `0x00`-`0x07` 和 `0x78`-`0x7F`，因此即使固件接受其中部分地址，也不建议使用。

示例：将模块地址修改为 `0x20`：

```text
[0xFF] [0x20]
```

写入完成后，主机必须使用新地址继续通信。建议等待配置写入完成，并从新地址读取 `0xFF` 进行确认。写入 `0x00` 或大于 `0x7F` 的值会被忽略。

## 7. 主机访问示例

以下伪代码中的地址均为 7 位 I2C 地址。

### 7.1 读取按键数据

```c
uint8_t key_code;
i2c_read(device_address, &key_code, 1);
```

### 7.2 读取固件版本和当前地址

```c
uint8_t reg = 0xFE;
uint8_t info[2];
i2c_write(device_address, &reg, 1);
i2c_read(device_address, info, 2);
```

### 7.3 读取完整 UID

```c
uint8_t reg = 0xE0;
uint8_t uid[12];
i2c_write(device_address, &reg, 1);
i2c_read(device_address, uid, 12);
```

---

## 8. 使用注意事项

- 主机应在检测到 `IRQ` 低电平后优先读取 1 字节按键数据。
- 按键码在按键松开时产生；按住按键期间不会产生重复按键事件。
- 模块每次只返回一个按键码，不提供完整矩阵状态或多键组合状态。
- 寄存器读取与按键数据读取使用不同事务流程，请勿混用。
- 修改 I2C 地址后，应保存或重新发现新地址，避免设备在后续启动时失联。
